# 文案怎么生成，发送前看什么

## 文案的写法

提示词源码在 `frontend/src/services/rebroadcastPrompt.ts`。连接 AI、保存风格和开场时，会同步给转播编辑。自己的好文案作为附加范例保留，不当成本场事实。

每次最多生成一条候选：先抓一个原话支持的具体亮点，例如问题、反差或“第二招”；透露一点能看懂的内容，再留下值得来听的细节，末尾附本场入口。提示词包含六组教学输入与输出，小模型也能参照。

没有新信息时可以不出稿。范例中的人名、数字和情节禁止带入本场；嘉宾称呼不能仅凭话题猜测；回放不能写成正在直播。对应的原话摘录会保留给人核对。提示词降低错误概率，不能取代人工校对。

## 发送流程

打开审核卡片，先核对嘉宾、数字、事实和直播入口，再看完整正文。修改后先保存，再选择目标群并勾选确认，最后点发送。群列表默认不替你勾选。

后台要求正文与当前保存版本一致，检查人工审核标记并记录每个目标的发送状态。成功、发送中或结果未知的目标会被挡住，避免因重复点击再次发送；明确失败的目标可以重试。同一条内容被重新创建为另一条文案不属于同一回执，运营者仍需避免重复内容。

## 多位嘉宾

声音区分只能建立说话人标签，无法自动知道嘉宾真实姓名。请听原音并在发言人设置里匹配姓名；辨认不清时保留泛称。多个人同时说话、音乐和录音质量会影响结果。

极简流程提供常用操作；需要更多转写、发言人和知识资料设置时，可在当前网址后加 `?view=original` 使用完整界面。
