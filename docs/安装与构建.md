# 随听：安装与构建

随听基于 Backchannel 改造。普通使用者优先下载 macOS 安装包；Docker 和源码方式主要面向希望自己部署、修改程序的人。下面命令均从项目根目录执行，除非步骤明确要求进入子目录。Docker、源码及全新构建命令依据仓库配置整理；最终发布说明中的实测结果优先，不能把已有电脑运行成功等同于所有环境均已验证。

## 下载 Mac 安装包后

当前提供的是 **Apple Silicon（M1、M2 等）ARM64** 包，不是 Intel Mac 包。解压后把“随听.app”移动到“应用程序”，再打开。

桌面包包含 Python 运行环境、后端、网页界面、PostgreSQL 和说话人区分用的两份 ONNX 模型。无需另外安装 Python、Node.js、PostgreSQL，也不需要安装 `openai-whisper`。

当前打包方式使用本地临时签名（ad-hoc），**没有 Apple Developer ID 身份签名，也没有完成 Apple 公证（notarization）**。`codesign --verify` 通过只说明包内签名结构一致，不代表 Apple 公证通过。首次打开如被系统阻止，可核对下载来源及发布页校验值后，通过 macOS“系统设置 → 隐私与安全”允许本次打开；不要关闭系统的全局安全检查。

推荐使用 Chrome 或 Edge。听电脑声音仍需在浏览器弹窗中选择能分享声音的来源，并允许相应系统录音权限；程序不会跳过浏览器授权。

## 哪些已经带上，哪些需要首次下载

- **语音转文字**：`onnx-asr`、`onnxruntime`、NumPy 和 Hugging Face 下载组件包含在桌面运行环境中。默认模型是多语言 **Whisper Base**，通过 ONNX 执行，不依赖 PyTorch。模型权重在首次使用时从 [Whisper Base ONNX 模型仓库](https://huggingface.co/istupakov/whisper-base-onnx) 下载，已核实的本地缓存约 399 MB；网络可用时应在开播前完成首次下载。
- **分辨不同声音**：包内包含 `silero_vad.onnx`（约 2.3 MB，检测说话片段）和 `voxceleb_resnet152_LM.onnx`（约 79.2 MB，用来区分声音）。它们不会自动知道嘉宾真实姓名，仍需在界面中匹配姓名。
- **数据库**：桌面构建下载并内置 PostgreSQL **16.4.0**；Docker 使用 PostgreSQL 16 容器。它保存本机的场次、文字和设置，不需要另购数据库服务。
- **FFmpeg**：Mac 桌面包默认没有附带。直播上传的是 PCM 音频，通常不需要它；导入 MP3/M4A、部分录音格式解码需要。需要这些功能时，可在已经安装 Homebrew 的 Mac 上执行 `brew install ffmpeg`。Docker 后端已经安装 FFmpeg 和 libsndfile。
- **GeWe**：外部微信接口服务，使用自己的账号、API Token、appId 和在线微信节点，不是需要安装的 Python 包。具体配置见 [GeWe 连接说明](GeWe.md)。没有配置 GeWe 也可以生成、修改和复制文案。
- **写文案的 AI**：与语音识别是两件事。国产及海外模型通过“连接 AI”配置；模型服务可能需要 API 额度。使用本地文字模型时，需要自己启动相应服务，Whisper 本身不会写转播文案。

可选 Parakeet v2 主要用于英文，不应代替中文默认模型。Sortformer 是另一种更重的说话人区分方案，会引入 PyTorch、NeMo 等依赖；普通直播电脑无需安装，下面采用关闭它的轻量设置。启用其他可选功能可能另外下载模型，例如隐私识别模型；这些不包含在 Whisper 的约 399 MB 中。

Whisper 缓存保存在应用 `DATA_DIR/asr-models/whisper-base`。桌面版由启动器设置 `DATA_DIR`，实际位置可从应用“打开数据文件夹”确认；Docker 默认是容器内 `/app/data/asr-models/whisper-base`，由数据卷持久保存。

如果首次模型下载中断，**先退出随听**，只把 `asr-models/whisper-base` 这个目录重命名为 `whisper-base.incomplete`，然后重新打开并下载。不要删除整个数据目录、数据库或录音。当前加载器可能把非空的半截模型目录视为已有模型，重命名可保留现场并重新下载。

## Docker 运行

准备 Docker 与 Compose 插件。在项目根目录复制配置：

```bash
cp .env.example .env
```

用文本编辑器在 `.env` 中添加或调整以下设置。`POSTGRES_PASSWORD` 应填写自己的密码，下面的文字只是占位符；不要把填写后的 `.env` 上传 GitHub。

```dotenv
POSTGRES_USER=callhelper
POSTGRES_PASSWORD=请替换为自己的数据库密码
POSTGRES_DB=callhelper
INSTALL_SORTFORMER=false
BACKEND_RELOAD=false
DATA_DIR=/app/data
```

启动：

```bash
docker compose up --build -d
docker compose ps
docker compose logs --tail=50 backend
```

打开 [本机随听](http://localhost:3000)。后端健康接口是 [http://localhost:8001/api/health](http://localhost:8001/api/health)。首次镜像构建会下载 Python/Node 依赖、ONNX 说话人模型；首次选择本地语音识别还会下载 Whisper。

`pgdata` 数据卷保存数据库，`backend_data` 保存应用文件和模型。日常停止用 `docker compose down`，不要附加删除数据卷的参数。

GeWe 配置须保存在容器能读到且可持久保存的位置，例如挂载目录并设置 `SUITING_WECHAT_DIR`；具体命令与说明见 [GeWe 连接说明](GeWe.md)。容器中的 `localhost` 指容器自己；如果文字模型服务运行在 Mac 宿主机上，连接地址需使用 `host.docker.internal` 和该服务端口。

## Mac 源码运行

以下步骤使用本机 PostgreSQL 16，适合需要修改代码的人。已安装并配置好这些工具时不必重复安装。

```bash
brew install python@3.12 node@24 postgresql@16 ffmpeg
export PATH="$(brew --prefix python@3.12)/bin:$(brew --prefix node@24)/bin:$(brew --prefix postgresql@16)/bin:$PATH"
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
python backend/scripts/download_models.py
brew services start postgresql@16
createuser --pwprompt suiting
createdb -O suiting suiting
cp .env.example backend/.env
```

上面最后两个数据库命令只在首次创建用户和数据库时执行。`createuser` 会让你输入数据库密码。然后在 `backend/.env` 中填写实际密码：

```dotenv
DATABASE_URL=postgresql+asyncpg://suiting:你的数据库密码@127.0.0.1:5432/suiting
BATCH_TRANSCRIBER_MODEL=local-whisper-base
INSTALL_SORTFORMER=false
```

连接字符串中的密码若含 `@`、`/`、`:` 等特殊字符，需按 URL 规则编码。API 密钥可以稍后在“连接 AI”中输入。

启动后端，第一个终端保持运行：

```bash
source .venv/bin/activate
export DATA_DIR="$PWD/.local-data"
mkdir -p "$DATA_DIR"
cd backend
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

在第二个终端进入同一个项目根目录，启动前端：

```bash
export PATH="$(brew --prefix node@24)/bin:$PATH"
cd frontend
npm ci
npm run dev -- --host 127.0.0.1
```

打开 [http://localhost:3000](http://localhost:3000)。Vite 自动把 `/api` 和 `/ws` 请求转发到本机 8000 端口。程序启动会创建缺少的表并补充兼容字段；已有数据库升级前应先备份。

## 构建 Mac ARM64 桌面包

需要原生 Apple Silicon、Python **3.12**、Node.js **24** 和 Xcode Command Line Tools。先执行 `xcode-select --install`（已经安装时跳过），然后在项目根目录执行：

```bash
brew install python@3.12 node@24
export PATH="$(brew --prefix python@3.12)/bin:$(brew --prefix node@24)/bin:$PATH"
python3.12 -c 'import platform; print(platform.machine())'
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt -r desktop/requirements.txt
cd frontend
npm ci
npm run build
cd ..
python backend/scripts/download_models.py
python desktop/scripts/download_pg.py
pyinstaller desktop/backchannel.spec --distpath dist --workpath build --noconfirm
```

架构检查应显示 `arm64`。不要用 Rosetta 下的 x86_64 Python 构建 ARM64 包。PostgreSQL 下载脚本按当前 Python 进程的架构选择二进制文件；更换架构时须使用干净构建目录，不能沿用另一架构的 `desktop/pgsql`。

当前底层 spec 产出 `dist/Backchannel.app`，以下保留底层内部可执行文件名，只修改对外应用名和显示名称：

```bash
ditto dist/Backchannel.app dist/随听.app
python - <<'PY'
from pathlib import Path
import plistlib
path = Path("dist/随听.app/Contents/Info.plist")
info = plistlib.loads(path.read_bytes())
info.update(CFBundleDisplayName="随听", CFBundleName="随听",
            CFBundleShortVersionString="0.1.3", CFBundleVersion="0.1.3")
path.write_bytes(plistlib.dumps(info))
PY
codesign --force --deep --sign - dist/随听.app
codesign --verify --deep --strict dist/随听.app
mkdir -p release-assets
ditto -c -k --keepParent dist/随听.app release-assets/Suiting-macos-arm64.zip
shasum -a 256 release-assets/Suiting-macos-arm64.zip
```

上面版本号对应随听 `v0.1.3`，以后发布需同步修改。本项目已使用独立 Bundle ID `com.codingwithyiqi.suiting`，并停用上游自动更新；随听从自己的 GitHub 发布页更新。若项目 spec 已直接产出 `随听.app`，跳过复制和名称调整，只进行验证、压缩及校验。

**必须保留软链接和资源文件。** 用 `ditto` 复制、压缩、解压 `.app`，不要逐个复制可执行文件。`desktop/backchannel.spec` 收集的 `onnx_asr` 预处理数据，以及 `onnx-asr`、`huggingface-hub`、`tqdm` 的包元数据都不能移除，否则程序可能正常启动，但语音识别失败。

开发者如果以后提供正式 Developer ID 签名及 Apple 公证，需要另行配置 Apple 证书、签名和 `notarytool` 流程；上述 `--sign -` 没有完成这些工作。

## 发布前验证

先运行与本次修复有关的轻量路径测试：

```bash
python -m unittest discover -s backend/tests -p test_speaker_model_paths.py -v
```

已有桌面烟雾测试会使用临时数据目录，检查全新数据库初始化、健康接口、本地语音运行库资源和正常关闭：

```bash
python desktop/scripts/smoke_test.py
```

该脚本默认检查 `dist/Backchannel/Backchannel`，不直接证明压缩包内 `.app` 正常。还要把 ZIP 用 `ditto -x -k` 解压到新位置，对解压后的应用设置单独的 `BACKCHANNEL_DATA_DIR`、`BACKCHANNEL_HEADLESS=1` 进行启动和停止验证，确保不使用维护者已有数据库、密钥和模型缓存。健康接口通过后，检查 `/api/diagnostics/local-asr`；它证明运行库可用，**并不证明模型权重已下载或真正转写成功**。

最终应再用公开或专门制作的中文样本完成首次 Whisper 下载和真实转写，检查说话人区分、人工审核文案、连接自有 AI，以及仅向自己的文件传输助手试发。实际调用外部模型或 GeWe 需要测试者自己的账号。测试结果应明确区分“已实测”和“仅提供配置”，不要将所有供应商写成逐一验证过。

仓库保存源码、锁文件、配置样例和说明；发布页保存安装 ZIP 及 SHA-256。不要复制任何个人应用数据目录：其中可能包含录音、会议记录、API 密钥、GeWe 群列表和发送回执。部分 Python 依赖仍使用版本范围，当前流程可用于重建功能包；它不是逐字节可复现构建的承诺。

## 本次成品包的封装方法

v0.1.2 沿用已验证的 Backchannel v0.6.5 Mac ARM64 运行库，替换为本仓库全部 `backend/app`、`desktop/bcdesktop` 和启动器源码，并放入重新构建的前端。脚本逐一核对源码模块，检查其余依赖模块未变，随后重新临时签名。使用的是本机已有且修复过语音运行库资源的应用副本，不能把任意上游安装包都视作等价输入。

维护脚本 `scripts/repackage_macos.py` 需要 Python 3.12、`pip install pyinstaller==6.16.0`，及一个已经验证可用的底层 .app。它只复制给定安装目录，不读取用户数据库或账号配置。全新环境优先按上面的完整源码构建步骤操作。

```bash
python scripts/repackage_macos.py --source-app /绝对路径/原应用.app --output-app /绝对路径/随听.app --frontend-dist /绝对路径/frontend/dist
```

输出路径必须尚不存在。重新封装后仍需独立数据目录启动、语音运行库检查和压缩包解压验证；模块核对不能代替运行验证。
