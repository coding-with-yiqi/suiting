# 给随听连接你的 AI

随听把听到的内容整理成转播文案。你可以选择自己已有账号的模型服务，也可以连接本机模型。**文案生成后会先留给人审核，只有勾选目标并确认发送，才会通过微信发出。**

资料核对日期：2026 年 9 月 23 日。模型会更新或下线，请从服务商控制台复制当前可用的模型 ID，不要只凭网页上的产品名称填写。

## 先分清这几件事

**听清声音：语音识别模型负责。** Whisper 等语音识别模型把声音变成文字；它们不是下面用于写文案的聊天模型。语音识别的安装与选择请按项目安装说明操作。

**写好文案：下面的 AI 负责。** 云端 API 模型通常需要基础地址、API Key 和模型 ID 三项信息。本地模型则需要先在自己的电脑上安装并启动模型服务。

**发送微信：GeWe 负责。** GeWe 是独立的微信接口服务，需要自己的服务账号、已登录的微信设备和接口凭证；它不是 Whisper，也不是聊天模型。随听调用它发送审核通过的正文。配置方式以 [GeWe 官方文档](https://doc.geweapi.com/) 为准，不要把自己的 Token、设备 appId 或群资料上传到 GitHub。

**底层项目：Backchannel。** 随听基于 [Backchannel 开源项目](https://github.com/talberthoule/backchannel) 再封装，沿用其音频采集、转写、说话人处理及会议基础能力，增加中文使用流程、转播文案和人工审核发送。Backchannel 的 [原项目说明](https://github.com/talberthoule/backchannel#readme) 与 MIT 许可应随分发保留。

## 配置时怎么填

- **基础地址（Base URL）**：复制下面对应服务商的地址；通常不要再加 `/chat/completions`。
- **API Key**：在对应服务商的开发者平台创建，不是网页登录密码。
- **模型 ID**：从开发者控制台、官方模型列表或接口返回的列表中复制。选择能接收文字并输出文字的聊天模型。

“能列出模型”和“能成功写文案”是两种检查。有些服务不提供统一的模型列表接口，仍可以手填模型 ID 使用；成功列出模型，也不代表所选模型具备调用权限、余额或结构化输出能力。

随听需要 AI 按指定的 JSON 格式返回文案。JSON 可以理解为软件读取内容的固定格式；普通用户不需要自己编写。接入时需要确认具体模型支持这一格式，生成结果仍需检查内容是否忠于原话。

## DeepSeek

**基础地址：** `https://api.deepseek.com`，官方也接受末尾带 `/v1` 的形式。

**模型怎么选：** 支持 `GET /models` 查询，也可以从官方控制台复制 ID 后手填。不要继续把已有下线公告的 `deepseek-chat`、`deepseek-reasoner` 当作长期默认值。

**输出要求：** 支持 OpenAI 兼容 Chat Completions 和 JSON Object。提示词应明确要求 JSON 并提供结构示例；仍需检查空结果、截断结果和字段是否齐全。

**验证情况：** DeepSeek Flash 已在本机用短素材实际试写过；这不代表所有 DeepSeek 型号、长场直播和不同账号都已完成验收。

官方资料：[开始接入](https://api-docs.deepseek.com/) · [查询模型](https://api-docs.deepseek.com/api/list-models/) · [JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)

## Kimi / Moonshot

**基础地址：** 中国区 `https://api.moonshot.cn/v1`；国际区 `https://api.moonshot.ai/v1`。使用与自己开发者账号对应的入口。

**模型怎么选：** 支持 `GET /models` 查询，也可以从开放平台复制模型 ID 后手填。

**输出要求：** 支持 OpenAI 兼容 Chat Completions、JSON Object 和 JSON Schema。最终文案取返回的 `content`，不要把思考过程 `reasoning_content` 当作文案。当前部分模型固定采样温度，官方建议不显式传入 `temperature`；通用的“温度 0.7”配置可能导致报错。

**验证情况：** 已核对官方协议，待使用者用自己的密钥和所选模型实际验收。

官方资料：[中国区接入](https://platform.kimi.com/docs/get-api-key) · [国际区官方配置](https://moonshotai.github.io/kimi-code/en/configuration/providers) · [查询模型](https://platform.kimi.com/docs/api/list-models) · [参数限制](https://platform.kimi.com/docs/api/models-overview) · [JSON 输出](https://platform.kimi.com/docs/guide/response_format)

## 通义千问 / 阿里云百炼

**基础地址：** 北京地域可使用 `https://dashscope.aliyuncs.com/compatible-mode/v1`。官方当前推荐业务空间专属地址：`https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`，其中 `{WorkspaceId}` 要替换成自己的业务空间 ID。

**地域怎么选：** 新加坡等地域使用各自的地址，API Key 必须与地址所属地域一致。请从控制台复制，不要混用不同地域的 Key 和地址。

**模型怎么选：** 可以从控制台复制模型 ID 后手填。官方查询模型接口是 `/api/v1/models`，不是在上述兼容基础地址后简单追加 `/models`；返回结构也需要单独处理。

**输出要求：** 支持 OpenAI 兼容 Chat Completions。JSON Object 的可用性与具体型号、思考模式有关；提示词中必须出现“JSON”。不是所有千问、视觉或音频模型都适合这个文案入口。

**验证情况：** 已核对官方协议，待使用者用自己的密钥和所选模型实际验收。

官方资料：[兼容地址与地域](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope) · [查询模型](https://help.aliyun.com/zh/model-studio/list-models) · [JSON 支持范围](https://help.aliyun.com/zh/model-studio/qwen-structured-output)

## Anthropic Claude · 实验性兼容

**基础地址：** `https://api.anthropic.com/v1/`。

**模型怎么选：** 从 Claude 开发者控制台复制模型 ID 后手填。官方原生 `GET /v1/models` 可用，使用 `x-api-key` 与 `anthropic-version: 2023-06-01` 请求头；不要假定它与通用 OpenAI 模型列表调用完全相同。

**输出限制：** 官方确实提供 OpenAI SDK 兼容层，但会忽略 `response_format`，也会忽略工具定义中的 `strict`。因此，设置 JSON Object 并不能保证它强制返回所需格式。此入口标为实验性兼容，需要靠提示词、解析和校验检查结果；格式错误时应提示失败，不能直接当作可发送正文。

要获得 Claude 原生的严格结构化输出，需要另外适配原生 Messages / Structured Outputs；不能把当前兼容入口描述成已经完成这项适配。官方也将兼容层主要定位为模型评估用途。

**验证情况：** 已核对官方兼容范围及限制，待使用者用自己的密钥实际验收。

官方资料：[OpenAI SDK 兼容限制](https://platform.claude.com/docs/en/cli-sdks-libraries/libraries/openai-sdk) · [原生模型列表接口](https://platform.claude.com/docs/en/api/models/list)

## 本地 Ollama

**基础地址：** 默认是 `http://localhost:11434/v1/`。如果客户端要求 API Key，本机默认 Ollama 可填 `ollama`；官方说明该值会被忽略。

**模型怎么选：** 先安装并启动 Ollama、下载需要的模型，再选择本机已有的模型。兼容接口支持 `/v1/models`；也可以用 `ollama list` 查看并复制完整模型名。

**输出要求：** 支持 OpenAI 兼容 Chat Completions、JSON 模式及 `response_format` 的相关字段。实际文案质量和速度取决于模型、量化方式及电脑性能，需要与直播软件同时运行检查；不要只凭参数量判断电脑能否负担。

**验证情况：** 已核对官方协议，尚未把任意本地模型视作已完成本机直播场景验收。此处说的是本地模型；Ollama 云模型另有登录和计费规则。

官方资料：[Ollama OpenAI 兼容说明](https://docs.ollama.com/api/openai-compatibility) · [Ollama 官网](https://ollama.com/)

## 自定义兼容服务

如果使用自建服务器或其他服务商，填写其官方提供的 **OpenAI Chat Completions 兼容基础地址、凭证和模型 ID**。不要把网页聊天地址、Responses 专用入口或 Anthropic Messages 专用入口直接填进来。

需要逐项确认：能否接收 `messages`、能否返回 `choices[0].message.content`、是否支持所需 JSON 格式。模型列表接口属于可选能力；可手填模型不代表文本生成已经成功。接入前用一小段无敏感信息的素材检查格式、事实准确性和等待时间，再用于正式直播。

## 网页会员、CLI 额度，不等于 API 免费

网页登录会员、Codex CLI / Claude Code / Kimi Code 等工具的套餐，以及开发者 API 是不同的使用入口。能登录聊天网页，不代表已经取得 API Key；能使用某个 CLI，也不代表可以无限、免费地调用其底层 API。

通过已登录 CLI 工作时，是否使用已有套餐额度、是否另行计费，以及允许哪些使用场景，均以对应工具当前的账号方式与套餐规则为准。直接填写 API Key 时，通常按开发者平台的 API 规则计费。安装一个 SDK 或接入工具本身，不会赠送模型额度。

OpenAI 与 Anthropic 官方都明确说明，网页订阅与 API 分开计费。其他服务商也应分别检查开发者平台余额和套餐适用范围。

官方资料：[ChatGPT 与 API 分开计费](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform) · [Claude 订阅与 API 分开计费](https://support.claude.com/en/articles/9876003-i-have-a-paid-claude-subscription-pro-max-team-or-enterprise-plans-why-do-i-have-to-pay-separately-to-use-the-claude-api-and-console)

## 开始正式使用前

用自己的账号和所选模型，先完成一次短素材试写：确认能生成候选文案、没有编造嘉宾观点、没有遗漏直播入口，再检查人工审核窗口。微信联调先发给自己的文件传输助手；确认收件人和正文后，再选择真实群。

本说明区分“官方协议已核实”和“已经真实调用成功”。除上文明确标注的 DeepSeek Flash 本机短素材试写外，不宣称其他服务商或型号已全部真实测试通过。
